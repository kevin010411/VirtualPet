# Sequence audio firmware implementation and verification

2026-10-13. The authoritative product and wire specifications remain in the
Web repository, `.scratch/sequence-audio/spec.md` and
`contracts/runtime_table_v19.json`. Existing SD packages must be re-exported
for firmware accepting Runtime Table v19. Pet persistence stays at v18.

## Implementation

`ENABLE_SEQUENCE_AUDIO` defaults to zero. The enabled build loads only bound
Action audio references and streams `/audio.data`; it adds no asset scans,
decode-only validation, or whole-file CRC checks. The exporter owns format,
duration, ownership, and reference validation.

`SequenceAudioPlayer` exposes preparation, start, monotonic playback time,
stop, and the first execution error. `AnimationController` prepares its audio
buffer before rendering the initial scene. The completed initial frame transfer
starts the sample clock. Visual frame selection follows consumed samples;
after EOF or failure it continues from the original monotonic start time.
Segment metadata is cached before playback. Repetitions and following segments
share one audio origin and never commit effects or tracked counts again.

Long audio continues buffered PCM with declining amplitude for 160 samples
(20 ms) when the visual sequence finishes. Accepted replacement, cancellation,
battery/fatal routing, and STOP use immediate stop. Finite playback blocks idle
sleep; the existing generic whole-sequence looping seam permits idle sleep and
restarts both tracks at the loop boundary. No infinite User Action authoring
option was added. Button beep writes cannot toggle the amplifier while audio
or its fade owns it. Wake redraw does not restore a sample position.

The STM32F103 target driver uses PA2 / TIM2 channel 3 for PWM, TIM4 update for
8 kHz pacing, DMA1 channel 7 for circular halfword transfers, and PA4 amplifier
enable. Two 512-sample halves use 2048 bytes, with a 512-byte SD read scratch.
SD refill happens in the main loop, never in IRQ. An unrefilled half stops
output and records underrun; SD and hardware failures likewise stop sound.
DMA stops before amplifier disable. The carrier is 281250 Hz at a 72 MHz timer
clock. PA9 backlight remains on TIM1. USART2 TX and I2C1 RX share DMA channel 7
and must remain unused; future TIM2/TIM4 features need explicit arbitration.
The code still targets `genericSTM32F103C8`. GD32 board identity, peripheral
equivalence, and actual timer clocks require device acceptance.

The source mapping was checked against the installed STM32duino F103 pin
table and [ST RM0008](https://www.st.com/resource/en/reference_manual/cd00171190.pdf).
TIM4 uses the framework's
[HardwareTimer interrupt dispatch](https://github.com/stm32duino/Arduino_Core_STM32/wiki/HardwareTimer-library),
avoiding a duplicate framework IRQ handler.

## Software evidence

`test/sequence_audio/run_host_test.ps1 -FixtureRoot <export-directory>` consumes
real public-editor-save/export fixtures generated by the Web script
`scripts/generate_sequence_audio_fixtures.py`. The firmware parser reads the
actual v19 runtime binary, and BundleReader reads exported shared/species pack
metadata. Renderer transfers, sample output, and controllable time/I/O are
host substitutes. No handwritten binary replaces the public export evidence.

Passing fixtures: `long_audio` (80000 samples), `short_audio` (800 samples),
`no_audio`, `muted`, and `feature_off`. Silent fixtures use `-Silent`.
Coverage includes first frame before samples, frame catch-up, segment repeats,
short/long audio, accepted replacement, cancellation, whole-cycle restart,
finite/loop sleep gates, late EOF, read/prepare failure, hardware-start failure,
and underrun. Real Pet / PetBehaviorRuntime commits an observable +40 once.
The host enables the existing tracked-Action registry for the fixture's Action
to prove that execution counts also remain one. PCM-driver IRQ timing and SD
refill under TFT load are not executed by this substitute.

Additional passing checks: Game startup sequence-interruption subset,
RTC/power host, Pet Behavior runtime for 6/10/12 Stats plus animation-free
Actions, Pet persistence host, and `git diff --check`.

The full Game startup host still fails at `test/game_startup/test_main.cpp:767`,
`data.reloads == 1 && data.saves == 1`. The same failure was reproduced with
baseline HEAD Game, AnimationController, and PetBehaviorRuntime sources; the
root task independently confirmed it before the audio changes.

## Target build and capacity evidence

All audio-enabled translation units and timer/DMA configuration compile.
The standard 64 KiB C8 audio-enabled link fails only with FLASH overflow of
988 bytes. It is not a passing build for that hardware configuration.

For a measurable linked image, the isolated verification INI adds two variants
with the same `board_upload.maximum_size = 131072`, environment, input, and
optimization flags; only `ENABLE_SEQUENCE_AUDIO=1` differs. This diagnostic
linker allowance does not establish the physical MCU's Flash size.

| Configuration | Flash reported by PlatformIO | Static RAM | Result |
| --- | ---: | ---: | --- |
| Standard project_12, audio disabled | 63132 B | 7464 B | Pass, 64 KiB limit |
| Diagnostic 128 KiB, audio disabled | 63132 B | 7464 B | Pass |
| Diagnostic 128 KiB, audio enabled | 66228 B | 10468 B | Pass |
| Standard 64 KiB, audio enabled | No linked image | No linked image | FLASH overflow 988 B |

The controlled diagnostic difference is +3096 B Flash and +3004 B static RAM.
Static RAM excludes heap allocations and runtime peak stack use; no peak RAM
or synchronization-error bound is claimed. The feature includes cached segment
timings and player state within the heap-owned AnimationController.

Build INI and raw logs are preserved in the integration workspace's ignored
`.pio/sequence-audio-firmware-evidence/` directory, outside temporary worktrees.

## Deferred device acceptance

Actual SD/TFT/PWM behavior, continuous refill timing, audio start latency and
synchronization error, RC frequency response, amplifier pop/transients, speaker
distortion, peak heap/stack, low battery, three-AAA voltage droop, and power
consumption remain unmeasured. Host and target compilation evidence do not
establish those results. No product feature was removed to fit current Flash.
