# RTC 與按鍵恢復驗證

2026-10-12。

## 已重現的韌體問題

- RTC 同步失效時，原本的 `readSeconds()` 會等待約 1000 ms，阻塞按鍵輪詢。
- `hasPendingTime()` 同時鎖住左右選單切換。補時或動作動畫尚未結束時，游標必須等待。
- RTC 讀取失敗會將遊戲設為未就緒，永久停在 `RTC clock error`。

## 修復行為

正常執行與 STOP 喚醒後，RTC 恢復以分步輪詢進行，不等待晶振或同步旗標。
保留有效的 RTC 計數器；備份域已失效時才重新建立計數器並更新 epoch。
SessionClock 保留單調的遊戲時間，防止重設計數器造成巨量無號補時，
也避免把清醒期間已計入的時間再補一次。

RTC 不可用時，以 millis 維持清醒期間的進度並禁止 STOP；RTC 恢復後再使用
RTC 計入待機時間。此降級策略會增加耗電，不代表晶振或供電問題已修好。
若備份域在 STOP 期間丟失，該段睡眠時間無法可靠還原，不推算未知時間。
整機斷電／重啟仍只保有既有的持久化存檔，不新增跨重啟時間 checkpoint。

依使用者最新要求，一般單鍵在輪詢首次看到按下時即派送，不等放開，
不等待 30 ms 去彈跳；保留 250 ms 短按間隔，按鈕派送在遊戲時間更新前。
作弊模式單鍵仍在放開時區分短按與長按；補時期間不再暫存確認；
Game 的未完成補時與進化輸入限制仍有效。提示音維持非阻塞。

`ENABLE_DAILY_POST_PROCESSING` 依使用者要求重新預設為 1，啟用每次換日的
解鎖查詢、圖鑑結算、定期存檔及自動進化查詢（包含換日前的進化檢查）。
普通存檔維持每 4 秒一次，事件存檔與 RTC 補時批次存檔保留。
重新編譯為 0 可暫停這段自動處理，寵物日、數值與基礎動畫仍推進。
