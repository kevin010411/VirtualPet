# 四款小遊戲提案

四份文件都是未批准為正式契約的設計提案，尚未實作／試玩／驗收。
容量與預設值仍須確認；正式跨層欄位、二進位 section／版本留在 Web 定案。

- [時機判定／打靶](01-timing-challenge.md)
- [連按競速／除草](02-progress-race.md)
- [指令反應／口令](03-instruction-response.md)
- [路線選擇／地雷](04-lane-traversal.md)

共通創作流程：設定規則、指派原尺寸素材、配置結果效果、三鍵預覽、保存／套用並加入入口。
缺素材可保存草稿但不可匯出；Web 驗證 ID、尺寸、結果覆蓋與 profile 容量。
韌體只做固定容量讀取與 SD／TFT 執行失敗處理，不重新做產品／資產驗證。

純遊戲模組提供 `start(config, now, ...)`、`step(now, input, output)`、`cancel()`，
不讀 SD／TFT／Pet Stats。Controller 管入口、輸入及原子效果提交，renderer 消費有限視覺狀態。
新增結果提交 seam 不直接呼叫普通 User Action，避免附帶動畫／日暫停語意。

待确认政策：遊戲專用按下時間戳／30 ms 多鍵識別窗口、左右同按一秒退出、
暫停 PetClock 且不補算遊戲耗時、活動阻止 STOP、結果 15 秒自動返回。
普通按鍵目前首次按下即派送；遊戲輸入提案不能被當成現有行為。
不更改全域兩秒日、30 秒降亮／120 秒 STOP。RTC 暫時不可用已有恢復路徑，
是否中止遊戲需在新契約確認。

只保留一個固定活動 session，依已套用快照產生模板 flags 與容量；未用模板不連結。
退出／提交前故障無獎懲（逐步遊戲保留已提交步驟）；提交後視覺失敗不回滾。
沿用既有保存路徑，不保存半場／seed，不承諾跨重啟 exactly-once。

驗收需包含 Web 草稿／匯出、同快照跨層 fixture、純邏輯 host、模板裁切建置，
以及真實按鍵延遲、SD／TFT、低電壓與返回後 RTC／STOP。現有 STM32 build 不證明 GD32 實機行為。
