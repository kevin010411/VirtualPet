# 連按競速與事件反應遊戲計畫書

日期：2026-10-11。狀態：設計提案，尚未實作、試玩或驗收。

本計畫將兵兵「除草競賽」抽象成連按推進、對手競速及有限事件反應模板，可用於划船、挖礦與修理。本文是使用流程提案與韌體計畫；正式匯出契約需先在 Web 定案，不取代或複製跨層規格。

## 1. 玩家會玩到什麼

確定鍵每次有效按下增加進度。玩家與自動前進的對手比誰先完成；也可選倒數模式，要求在時間內完成。偶爾出現事件，玩家需改按左或右解除；反應錯誤、逾時或操作過快會造成一次失誤與暫停。失誤達上限則提前結束。

首版不加入自由戰鬥、敵人 AI、任意事件腳本或不同事件連鎖。

## 2. 創作者如何設計

1. 新增「連按競速與事件反應」，命名並選擇「對手競速」或「倒數挑戰」。切換模式只顯示相關設定。
2. 設定目標進度、每次按下增加量，以及對手速度或倒數時間。預覽顯示所需有效按鍵次數與估算完成時間。
3. 決定是否啟用「操作過快」處罰；啟用時設定最小有效間隔與暫停時間，介面明示連按越快不一定越好。
4. 決定是否啟用反應事件。首版只提供一個事件型別，可設定提示素材、左／右任一鍵或指定一鍵、反應時限、發生間隔範圍。
5. 指派背景、玩家／對手姿態、進度顯示區、事件與暫停視覺。未啟用的模式不要求對應素材。
6. 設定「完成／未完成／失誤上限」三種終局的結果視覺與 Pet Stat 效果。
7. 用預覽測試事件與速度，保存、套用後指定選單入口；測試按鈕可強制事件出現，但不輸出到裝置。

畫布是模板專用區域，進度條由有限繪圖或有限圖片級距表示；不用為每個進度數值製作完整畫面。使用原尺寸圖片，Web 驗證素材與區域，不縮放或補邊。所有文字提示須走既有可用字形策略，否則由 Web 預先轉成圖片；不假設韌體新增中文字庫。

### 建議設定與初始上限

| 設定 | 首版提案 | 設定意義 |
| --- | --- | --- |
| 目標進度／每次增加 | 各 1–1000 | 每次增加不得超過目標 |
| 對手速度 | 每秒整數進度 1–1000 | 只在對手模式顯示 |
| 整場時限 | 5–120 秒 | 兩種模式都必須有有限時限 |
| 過快處罰 | 關閉或間隔 100–1000 ms | 平台去抖與遊戲處罰是兩件事 |
| 事件間隔 | 下限／上限 1000–15000 ms | 以有效遊玩時間計時 |
| 事件反應時間 | 300–5000 ms | 以提示顯示完成為起點 |
| 暫停時間 | 200–5000 ms | 暫停不能再次產生失誤 |
| 失誤上限 | 1–10，預設 4 | 第 N 次失誤立即進入失敗終局 |

以上上限是待建置驗證的提案。事件關閉時不匯出事件素材或計時設定；不能以隱藏的殘留設定影響遊玩。

### 兵兵配置範例

對手模式，確定推進，蛇事件接受左或右，連按過快或被蛇咬計一次暫停，第 4 次以中暑送醫結束。完成→體力 +30、戰技 +20；對手先完成→體力 +10；失誤上限→體力 −35、戰技 −10。

原企劃没有定義競速同時完成、事件逾時、速度與反應秒數。首版提議將逾時視為一次事件失誤；整場超時視為未完成。這些是新增語意，須確認後才能稱為兵兵設定。

## 3. 匯出與驗證提案

Web 保存穩定遊戲／素材／Pet Stat ID，投影到 runtime.bin 的數值索引。提議設定記錄包含模式、進度、速度、整場时限、過快處罰、事件計時及失誤上限；終局表固定三列，引用視覺與效果集合。

Backend 驗證模式互斥、速度與時限、有效進度、事件解除鍵、最小間隔、必要素材、三種終局完整度、效果引用與 profile。還須提示幾乎不可能完成的配置：例如理論最大有效按鍵進度仍無法在時限完成；前端可警告，是否阻止匯出需在正式規格定案。

資料／素材驗證在 Backend；韌體只作必要有界讀取與實際 SD/TFT 錯誤處理，不新增規則完整性檢查、全檔 CRC 或解碼掃描。二進位 section 與版本在 Web 定案；不能復用現有 Guess Game 的二元勝負格式冒充三種終局。

## 4. 韌體如何設計

### 模組與 interface

新增 `ProgressRace` module，外部只有 `start(config, now, randomSource)`、`step(now, input, output)`、`cancel()`。module 返回進度、提示角色、暫停狀態與單次結果事件，不讀 SD/TFT、不直接改 Pet Stats。隨機来源由 controller 注入，host 測試能控制事件時間。

`MinigameController` 負責入口、輸入與效果提交；顯示 adapter 僅重繪改變的進度區及事件提示。不是把遊戲邏輯放進 Renderer，也不是每個事件各自改能力值。

### 狀態與執行規則

`Inactive → Prepare → AwaitRelease → Running ↔ EventPending / PenaltyPause → Completed → Result → Inactive`。

- 首幀顯示完成並全放開後開始比賽，入口確定不增加進度。
- Running 的確定按下增加進度；左右單鍵無進度作用。按住不連加。
- 對手用有效遊玩時間與定點整數累計進度，保留除法餘數；不能依 tick 次數前進。
- 普通 Running 只維護一個事件倒數；事件結束後重新抽取下一間隔，禁止事件堆疊。
- EventPending 期間不增加玩家進度；指定解除鍵成功後回 Running，確定／錯鍵或 deadline 到期產生一次失誤。
- 若發生過快操作，該次確定不增加進度，且產生一次失誤。同一事件不同时以過快、錯鍵和逾時計多次。
- PenaltyPause 忽略作答，不重新計失誤。對手與整場倒數持續；事件倒數暂停。暫停結束清除按鍵殘留後回 Running。
- EventPending 時對手仍前進。若對手先完成，直接未完成終局；不等事件解除。
- 同一時間先處理有效輸入／事件逾時及失誤上限，再判玩家完成，再判對手完成，最後判整場超時。玩家與對手同一時間完成時玩家勝；已到失誤上限則優先失敗。這個順序是提案。
- 精確 deadline 的輸入視為逾時；跨時間 rollover 用 unsigned elapsed 計算。input 依 timestamp 排序處理，不受繪圖完成時間影響。

同時左右鍵作為退出手勢的一部分，不視為解除事件；「左或右任一鍵」指單鍵。活動最多 120 秒，不採用無限等待或忙等 delay。

## 5. 平台、退出與結算

目前 MinigameController 只有 Guess Game，需擴充模板路由與遊戲索引。ButtonInput 一般操作在放開時發送並有 cooldown；連按模板需要去抖後按下事件與時間戳，不能沿用選單 cooldown 吞掉過快操作，否則玩家永遠觸發不了處罰。去抖仍保留，不把彈跳當作弊或有效操作。

建議活動遊戲停用作弊手勢，左右兩鍵按住 1 秒退出，組合鍵消費單鍵候選事件並等待全放開。每次有效按下只計一次，暫停返回時也不能沿用 held key。

共用輸入 adapter 提議使用額外 30 ms 組合識別窗口；保留單鍵原按下 timestamp，deadline 或終局先等窗口內候選事件完成識別再決定。用原 timestamp 比較過快間隔與事件截止時間，不用 callback 發送時間。其他多鍵消費全部候選，不拆成多次單鍵操作。

提議進入前清空已到期寵物日數，活動期間 pause PetClock，退出 resume 且不補算遊戲耗時；這是對現有 minigame 時計行為的變更，須確認，保留普通兩秒 pet day 與獨立的就寢待辦。遊戲使用毫秒時計，不能用 PetClock 作反應時限。

活動期間阻止 STOP、維持可見亮度並服從低電壓限制；結果 15 秒自動返回，普通 30 秒調暗／120 秒 STOP 不變。低電壓、RTC 故障或讀圖失敗中止；解除後不自動恢復半場。

只在自然終局提交一次效果。退出、重啟與提交前故障無獎懲；已提交的值不因結果動畫失敗而回滾。使用既有 Pet Stat 原子效果、夾限與保存規則，不建立每日配額，也不自動帶入 User Action 的動畫或 Daily Change 暫停。整場 session 不保存，已提交值是否耐久保存在 SD 以現有保存結果為準。

## 6. 資源計畫

只保存玩家／對手進度、餘數、上次有效按鍵時間、事件／暫停截止時間、失誤數與結算旗標。固定容量，無事件隊列、動態配置或腳本。

profile 按套用快照連結用到的模板與容量；只保留一個活動遊戲儲存區。大量完整進度圖片會增加資源表與 SD 讀取成本，優先使用靜態背景與小區域更新。預覽渲染速度不能證明裝置連按反應速度。

當前建置目標 genericSTM32F103C8；各配置需要實測 Flash/RAM、stack peak、SD 延遲與電源行為，不能以此前靜態數字保證四模板同時容納，更不能當作 GD32 實機證據。

## 7. 實作順序與驗收

1. 確認暫停期間對手前進、同時完成、超時、過快判定與事件策略。
2. 在 Web 定案設定與二進位契約，完成兩種模式 UI、素材、三終局表及預覽。
3. 從真實編輯器快照匯出 fixture，完成純 module、輸入與顯示 adapter。
4. 接入原子結算／返回、PetClock 與 power，執行建置及實機驗收。

| 層級 | 必須驗證 |
| --- | --- |
| Web | 切換模式清理殘留、事件關閉不要求素材、三終局完整、引用、過快／時限範圍 |
| 跨層 | 相同匯出 fixture 的模式、事件鍵、速度、三終局效果與 profile；host inspector 完整檢查 |
| host | 最小按鍵間隔前後、恰好 deadline、事件與過快只扣一次、第 4 次立即失敗、同時完成、卡頓與時間 rollover |
| 回歸 | 選單 cooldown、作弊模式、按住不連加、退出不誤解除、一次結算、保存／動畫失敗 |
| 建置／實機 | 模板裁切、RAM/Flash 差額、連按可靠性、讀圖卡頓、TFT 小區域更新、低電壓與 RTC 返回 |

Web seed 只保证 Web 自己可重現；不保證韌體 PRNG 序列一致。跨層測試使用固定事件清單或可注入亂數，不比較兩套預設亂數序列。本次只有設計文件，未執行上述測試。
