# 指令辨識遊戲計畫書

日期：2026-10-11。狀態：設計提案，尚未實作、試玩或驗收。

把兵兵「口令反應」抽象成三鍵選擇與禁止操作題模板，可用于食材辨識、配送分類等。不是記憶序列或任意測驗引擎；本文只提出使用流程與韌體設計，正式新增契約由 Web repository 管理。

## 1. 玩家會玩到什麼

每題显示提示與三個物品，按左／確定／右選擇對應位置。提示若要求「不要選擇」，玩家必須在整個作答時間內不按任何作答鍵。每題可重新排列物品位置，整場完成後依答對數給獎懲。

首版固定三個物品、三個位置與兩種題型：選擇指定物品、全程不操作。不加入自由文字、物品組合、AND/OR 條件、題目腳本或跨題記憶。

## 2. 創作者如何設計

1. 新增「指令辨識」，設定名稱、題數與每題作答時間。
2. 建立三個物品：名稱、物品圖片、「選擇此物品」提示圖及「不要選擇此物品」提示圖。物品名稱只用於創作；装置可用提示圖避免新增字庫。
3. 設定禁止操作題比例與是否每題洗牌。UI 顯示本場實際題型數，避免把比例誤解成每題獨立抽籤的保證。
4. 在專用画布指定提示區、三個選項區與回饋區，指派背景及正確／錯誤圖片。三個實體鍵與畫面位置的關係在預覽中明示。
5. 配置答對數區間的結果視覺與 Pet Stat 效果；初始化一個完整覆蓋區間，允許逐步拆分。
6. 預覽提供「固定題目／固定排列」測試工具，確認禁止操作題、位置改變及超時。
7. 保存草稿、套用設定、接上選單入口，再匯出。缺少啟用題型的提示圖或結果表有缺口時拒絕匯出。

來源圖片保持像素與原尺寸；布局需符合目前裝置資源尺寸契約。這個遊戲畫布不表示現有 Screen Layout 已能綁定題目／剩餘時間，新增動態顯示需求需另行接入。

### 建議設定與初始上限

| 設定 | 首版提案 | 說明 |
| --- | --- | --- |
| 題數 | 1–20，預設 10 | 答對數範圍為 0..題數 |
| 選項數 | 固定 3 | 每題同時顯示三個物品 |
| 作答時間 | 500–10000 ms | 顯示就緒後開始 |
| 禁止操作題比例 | 0–100% | 題數以四捨五入計算，剩餘為選擇題 |
| 選项洗牌 | 每題或整場固定 | 重排位置，不改物品 ID |
| 回饋時間 | 100–1000 ms | 正確／錯誤顯示時不接收作答 |
| 結果區間數 | 至多 21 | 單一來源為答對數 |

禁止操作題數计算提案：`(題數 × 比例 + 50) / 100` 整數除法。固定長度題型表洗牌，确保整場數量；目標物品獨立抽取，允許連續重複。這些是設計选择，原企劃未定義比例或抽題分布。

### 兵兵配置範例

鋼杯、牙刷、筷子三物品，10 題，每題重新洗牌；「拿 X」選對應物品，「不拿 X」完全不操作。答對 0..10 題的智力效果依序：−20、−20、−15、−10、0、+10、+15、+25、+30、+40、+50。

反應時間與 no-go 比例待觀察原模擬器或確認，不以新預設值宣稱原版還原。

## 3. 匯出與驗證提案

Web 保存穩定遊戲／物品／素材／Pet Stat ID；物品不能靠陣列排序或名稱作身分。匯出投影成有界數值索引，設定包含題數、題型數、時限、洗牌模式、三物品素材引用及答對數結果表。

Backend 驗證恰有三個不同物品、有效圖片與尺寸、啟用題型提示齊全、題型數不超過題數、結果區間完整覆盖且不重疊、Pet Stat 效果及 profile。改名與畫布調整不能把提示連到另一物品；刪除物品時要求重新指派。

Frontend 立即提示，Backend 阻止不完整正式匯出。二進位欄位與版本在 Web 定案；runtime.bin／.data 仍是正式輸入。韌體不做題庫語意、圖片尺寸或全檔 CRC 驗證，只處理必要有界讀取及實際硬體失敗。

## 4. 韌體如何設計

### 模組與 interface

新增 `InstructionResponse` module，提供 `start(config, now, randomSource)`、`step(now, input, output)`、`cancel()`。隱藏抽題、排列與評分，外部只接收提示物品、題型、三位置映射、回饋與單次最終結果。

controller 傳入時間、按下事件與顯示就緒訊號；顯示 adapter 從物品引用繪製題目。遊戲 module 不讀圖、不查 Pet Stat 名稱、不提交 effects。亂數來源可注入固定序列供 host 測試。

### 狀態與判定

`Inactive → PrepareQuestion → AwaitRelease → WaitingAnswer → Feedback → NextQuestion / Completed → Result → Inactive`。

- PrepareQuestion 決定題型、目標與排列，一次生成，重繪不能重新洗牌。
- 先完成提示與三選項顯示，再要求全放開。畫面就緒與放開都完成後開始題目 deadline；等待放開最多 3 秒，未放開則中止整場，避免無限等待。
- 三位置固定映射為左鍵／確定鍵／右鍵。實體 previous／next pin 與畫面左右的映射以現有平台接線 adapter 為準，不能從 pin 名稱猜測方向。
- 選擇題：第一個作答按下立即決定正誤；正確是該位置對應目標物品。逾時是錯誤。
- 禁止操作題：任何單鍵或非退出多鍵的按下即錯；只有完整作答窗口沒有操作才正確，不能提前宣告答對。
- timestamp 恰好等於 deadline 時先結算時間到期：選擇題錯、禁止操作題對。到期後事件被丟棄，不送入下一題。
- 每題只增加一次正確／錯誤數。回饋期間忽略作答，下一題再全放開；長按不會跨題連答。
- 整場答對數只用於完成時的結果表；沒有每題與整場雙重獎勵。

狀態更新用單調毫秒時間與 unsigned elapsed；不以动画是否播放完畢决定答對。题目素材讀取過久或失敗則不啟動作答窗口，經 controller 中止並顯示實際資源錯誤。

## 5. 輸入與平台政策

目前一般 ButtonInput 是放開才送 callback 且帶 cooldown；no-go 必須偵測按下，否則按住到題末會被當成不操作。新增小遊戲的去抖按下事件，包含鍵遮罩與時間戳，保留選單既有操作。不能只利用 onLeft／onRight／onConfirm 三個放開 callback 還原此玩法。

提案停用活動遊戲中的作弊手勢。左右組合一經確認即中止本場並消費所有單鍵事件，不結算本題或整場效果；持續按住 1 秒返回選單，若提早放開也在全放開後返回，不重開題目。如此無法利用短組合反覆重試同題。結果畫面左右組合可直接返回。

輸入 adapter 須提供有界的組合識別窗口，例如 30 ms；這是去抖之外的輸入延遲，須實機驗證。單鍵候選事件在窗口後才送出，但判定仍使用原按下 timestamp；deadline 必須等窗口內事件完成識別再結算。不能先判 no-go 錯誤，再把同一組合判成退出。其他模板也應採用同一識別窗口，避免共用輸入有不同事件順序。

進入前先清空已到期日數；提議活動期間 pause PetClock，返回 resume 且不補算耗時。現有 minigame 仍推進寵物日，這是待確認變更；不改普通兩秒 pet day，也不定義就寢模式。no-go 不按鍵是有效遊玩，不能當作閒置。

活動遊戲阻止 STOP、保持可見亮度並服從低電壓限制；Result 最多 15 秒後返回。普通 30 秒調暗／120 秒 STOP 政策不改。低電壓、RTC 故障或 SD/TFT 資源讀取失敗中止整場，不恢復中間題。

## 6. 結算、容量與保存

全部题目完成才消費一次答對數结果。共用效果提交 seam 使用既有 Pet Stat 原子 effects 與夾限；它不是一個普通 User Action，不帶入動作動畫或 Daily Change 暂停。提交後結果視覺失敗不能回滾。

取消／重新啟動／提交前故障無獎懲；session 結算旗標防止同次運行重複提交。沿用已有保存流程與 fingerprint 語意，不保存題目、seed 或排列，不聲稱 SD 寫入失敗仍已耐久保存，不提供跨重啟 exactly-once。

只保留至多 20 個題型位元、三個位置索引、題號、目标、計時及計數；可用固定 bitset／陣列，不載入任意題庫或配置 heap。profile 按已套用快照生成設定、素材與結果容量；只有一個活動模板狀態，未使用模板裁切。

目前 genericSTM32F103C8 建置不代表 GD32 板驗證。需要量測 Flash/RAM、stack peak、提示圖 SD 讀取與 input latency，不能由 Web 預覽推斷硬體反應公平性。

## 7. 實作順序與驗收

1. 確認 no-go、组合退出、题型數量與計時起點；把正式契約放在 Web。
2. 完成三物品設定、提示素材、结果表與可控制題目的預覽。
3. 從真實快照匯出 fixture，實作纯 module、輸入與顯示 adapter。
4. 接入結算、PetClock、power 與返回，進行單模板／組合模板建置及實機驗收。

| 層級 | 必須驗證 |
| --- | --- |
| Web | 三物品不可重複、rename 保留映射、題型比例轉題數、提示缺圖、結果表缺口／重疊 |
| 跨層 | 相同 fixture 的物品角色、題型數、鍵位與智力結果；host inspector 完整驗證 |
| host | 每種排列的正解、no-go 任意按下、按住到題末、deadline 精確邊界、畫面就緒前不計時、跨題殘留、一次结算 |
| 回歸 | 組合退出不給獎勵、作弊停用、普通選單輸入、timeout／讀圖失敗、millis rollover |
| 建置／實機 | 模板裁切及記憶體差額、三實體鍵位、作答窗口公平性、无操作不睡眠、低電壓與 RTC 返回 |

Web seeded preview 只保证其自身可重現；跨層使用指定題型與排列 fixture，不要求 PRNG 相同。本次僅撰寫計畫，尚未執行測試。
