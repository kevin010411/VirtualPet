## 2026-10-21 已確認規則（第一至六輪）

- 做成通用模板，讓創作者自行放圖片；第一版固定三選項。
- 每個專案僅一組指令反應遊戲設定；簡單／困難由創作者設定，玩家不另選難度。
- 三個選項各在遊戲設定頁上傳一張 42×32 固定單幀圖片，不播放動畫。其他一般提示、「不 X」提示與答對／答錯回饋設為 system 動畫，可多幀或單幀。
- 提示使用原本 128×96 動畫區；下方三個選項各 42×32，兩個相鄰間隔各留白 1px，總寬 128px（42×3 + 1×2）。頂部 128×32 暫時沿用原畫面，不採先前清空的建議；新增題號／倒數疊圖未獲確認。
- 提示與回饋動畫依各自設定時間循環，到時間切換；作答從提示首幀與選項顯示完成、按鍵放開後開始，不等待整段動畫播完。
- 新增獨立的「指令反應遊戲」System Command，沿用八格入口配置；選取直接開始，既有猜拳遊戲保留為另一個命令。
- 提供禁止操作開關：關閉時只出一般題，不必上傳「不 X」圖片；開啟時須提供三個物品各自的「不 X」提示圖。
- 目標物與一般／禁止操作題型分別提供「相同機率」與「自訂權重」選擇。權重代表每題獨立抽取的機率，不保證整場固定題數，允許連續重複。三個物品的位置每題等機率洗牌。
- 作答時間可設定，預設每題 2 秒；提示與三個選項顯示完成、全部按鍵放開後才開始倒數，不另給提前觀察時間。
- 改為記錄固定作答時間內的按鍵，取代首次單鍵即鎖定答案；作答時間由創作者設定。
- 提供簡單／困難模式：一般題在簡單模式只要期限內曾按中目標就成功，其他錯按不影響；困難模式須曾按中目標且整段期間沒有按到其他選項。只有錯按或完全沒按都失敗；三鍵同按在簡單模式成功、困難模式失敗，但退出手勢優先。
- 禁止操作題在兩種難度都須沒有按鍵才成功。
- 每題一律等完整作答期限才判定，作答期間不顯示對錯；之後播放回饋。回饋時間由創作者設定，預設 0.5 秒。
- 從進入遊戲到結算／取消並返回原畫面，全程暫停寵物時計，離開不補算；遊戲倒數照常運作。
- 左右同按一秒退出，退出優先於答題；按住期間暫緩這次多鍵判定，未滿一秒放開則左右兩鍵都納入本題紀錄。中途退出整場無獎懲。
- 創作者可設定 1–20 題，預設十題。
- 全場共用「每題答對」「每題答錯」兩組效果，不依題號分別設定；各組可開關並選擇影響哪些寵物數值。
- 每題先記錄結果，完成全部題目後才依題目順序套用效果，逐次遵守數值上下限；不可直接加總取代。中途退出丟棄整場待結算結果。
- 不另加整場答對數的獎懲；不顯示「答對題數／總題數」，不保留獨立結果畫面。最後一題回饋播放完，完成數值結算後直接返回原畫面，不需另按確定或等待十五秒。
- 共用答對／答錯 system 動畫，預設回饋時間 0.5 秒；第三輪已同意未提供回饋素材時顯示內建勾／叉，沿用此 fallback。
- 作答時間可設 0.5–10 秒，預設 2 秒；回饋時間可設 0.1–10 秒，預設 0.5 秒。
- 本題只記錄作答起點（含）到期限（不含）的按下事件；剛好到期限的按下不算。按住不連發、不跨題當新答案；下一題先等全部按鍵放開。
- 期限前已開始的左右同按若跨過期限，暫緩本題結束，先完成退出判定；滿一秒取消整場，未滿一秒放開則只將期限前發生的按下計入原題。等待期間不開始下一題，也不延長原作答期限。
- 讀取素材或硬體執行在結算前失敗時中斷整場、無獎懲、不保存半場；能顯示時提示錯誤，返回後可重開。已成功提交的效果不因後續視覺失敗撤回或重複套用。
- 完全斷電不續接半場。斷電恰逢寫入的恢復能力須依保存機制實作與驗證，不預先承諾跨重啟 exactly-once。

## 規則摘要

| 一般題的期限內紀錄 | 簡單 | 困難 |
| --- | --- | --- |
| 只有目標鍵 | 成功 | 成功 |
| 目標鍵與其他鍵，不論先後 | 成功 | 失敗 |
| 只有非目標鍵 | 失敗 | 失敗 |
| 沒有按鍵 | 失敗 | 失敗 |
| 三鍵同按，且未觸發退出 | 成功 | 失敗 |

禁止操作題在兩種難度均為整段沒有按鍵才成功。左右同按退出優先，取消不套用任何題目效果。

## 實作前須落定的技術細節

以下是實作／驗證工作，不應混同為尚未決定的核心玩法，也不代表已取得實作或部署授權。

- Web 擁有 schema、system 動畫角色、固定命令 ID、權重數值表示與驗證、效果欄位、保存／套用與版本轉換；沿用既有 System 動畫分類，不另發明可改名的自訂動畫實例。
- Web 匯出負責素材尺寸、必填角色、有效權重、效果參照及容量驗證；缺必要素材可留草稿但不可匯出。回饋缺素材走已確認的勾／叉 fallback。
- 同一已套用快照驅動 runtime.bin、素材、profile 與模板裁切；不用猜拳的固定二元勝負流程替代本遊戲逐題紀錄。
- 確認 system 動畫的既有外觀／版本選擇規則與匯出角色；停用禁止操作時不要求其素材。頂部暫沿用既有視覺，不代表遊戲按鍵可觸發原入口命令。
- 實作前確認按鍵去抖／組合鍵辨識精度、跨題放開等待、RTC 故障與低功耗整合，不更改全域日長或一般操作規則。
- 結算應先在暫存數值依題序套用所有效果，再經既有提交路徑一次提交，避免中途出現半場效果；對照既有死亡／進化順序處理結算後生命週期。
- 明定提交／寫入失敗時的可觀察行為，驗證跨重啟恢復限制；Flash／RAM 與真實按鍵、SD／TFT、低電壓需目標硬體證據。

## 韌體狀態與契約

`InstructionResponse`：PrepareQuestion → AwaitRelease → Answering → Feedback → NextQuestion／Completed → Commit → Return。無獨立 Result 畫面。
左／確定／右對應位置，物品 ID 不隨位置變。禁止操作題全期限不按才算正確；
一般題依期限內記錄的輸入與難度判定，不採首次單鍵即結束；精確 deadline 的輸入不計入。
出題採獨立加權抽取；固定容量保存每題結果與當題輸入紀錄，不需保存無限事件序列。整場完成時一次提交依作答順序套用的效果，取消無效果；提交與持久化失敗的細節需對照既有保存路徑。

Web 穩定 ID 在匯出時投影為固定索引，設定、素材角色、結果與 effects 分開引用。
新增 wire 格式／版本先在 Web 定案；產品上限已確認，是否滿足目標硬體容量仍須以 linked build 與設備驗證確認。
