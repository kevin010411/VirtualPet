# 時機判定遊戲計畫書

日期：2026-10-11。狀態：設計提案，尚未實作、試玩或驗收。

本計畫將兵兵「打靶」抽象成可換主題的時機判定模板，適用於釣魚、節奏敲擊、料理翻面等。本文記錄創作者操作提案與韌體實作計畫，不是正式跨層規格；新增匯出契約須先在 Web repository 定案，不在此複製既有規格。

## 1. 玩家會玩到什麼

玩家看見沿軌道移動的指標，在指標進入命中區時按確定。一次按下消耗一個回合；命中、完美或失誤後顯示短暫回饋，再進入下一回合。全部回合完成才結算整場獎勵。

首版只提供一維往返移動與固定命中區，不加入自由瞄準、彈道、音訊節拍同步或多目標物理模擬。

## 2. 創作者如何設計

1. 在「小遊戲」新增「時機判定」，填寫名稱，例如「打靶」。
2. 設定回合數、指標往返週期與每回合時限；即時預覽速度，避免只看抽象難度等級。
3. 在專用遊戲畫布指定軌道、命中區及指標位置，選擇背景、指標、命中與失誤素材。
4. 選擇是否啟用完美區；預覽直接顯示其範圍，不再重複羅列畫面已表達的資訊。
5. 為「命中數區間」配置結果圖片／動畫與 Pet Stat 效果。新增遊戲時先建立一個覆蓋全域的無效果結果，之後可拆成更多區間。
6. 用三鍵預覽試玩；可指定測試起始相位，確認邊緣命中與逾時行為。
7. 保存草稿，套用設定後，把遊戲放入選單入口。缺素材或結果區間不完整時可保存，但不能正式匯出。

遊戲畫布是有限的專用顯示區域，不假設目前 Screen Layout 已能綁定遊戲內變數。圖片以原尺寸使用，不縮放、補邊或改變來源像素；不合區域時要求創作者換圖或調整允許的區域。

### 建議設定與初始上限

下列都是首版產品提案，須由目標 profile 建置決定最終容量。

| 設定 | 提案 | 說明 |
| --- | --- | --- |
| 回合數 | 1–20，預設 5 | 決定命中數的有效範圍 |
| 往返週期 | 500–10000 ms | 完成一次完整往返的時間 |
| 每回合時限 | 1000–15000 ms | 超時即失誤，不無限等待 |
| 命中區 | 正規化整數位置 0–1000 的閉區間 | 與實際素材寬度分離 |
| 完美區 | 關閉或命中區內的閉區間 | 完美也算一次命中 |
| 回饋時間 | 100–1000 ms | 回饋期間不接受下一次作答 |
| 結果表 | 至多 21 個整數區間 | 首版以命中數為唯一結果來源 |

完美次數可供回合回饋與測試觀察，首版不提供任意加權公式或多條件結果樹。速度固定，不加入自動難度調整。

### 兵兵配置範例

5 回合，以命中數映射戰技：0→−20、1→−10、2→0、3→+10、4→+25、5→+45。原企劃未提供精確移動週期與時限；這些值必須觀察原模擬器或由使用者決定，不能宣稱預設值就是原版。

## 3. 匯出前需要完成什麼

Web 使用穩定的遊戲 ID、素材 ID 與 Pet Stat ID；匯出時投影成直接數值索引。提議新增遊戲目錄、模板設定、素材角色及结果表；欄位位元組布局、section ID 與 runtime.bin 新版本由 Web 權威規格定案。

模板設定只需回合數、週期、時限、命中／完美區與回饋時間。結果記錄使用命中數上下界、結果視覺引用與效果集合引用，不保存玩家遊玩紀錄。

Backend 負責驗證區間完整覆蓋 0..回合數、無重疊、完美區包含關係、時間上限、素材尺寸與引用、結果效果，以及入口與 profile 的一致性。Frontend 提供立即反馈。韌體不重新檢查這些產品語意，也不掃描全部素材或 CRC。

資源繼續走 runtime.bin 與 .data；不是將原 HTML/WASM 放進 SD 執行，也不將遊戲結果硬塞進既有 Guess Game 的勝負欄位。

## 4. 韌體如何設計

### 模組與 interface

建議新增 `TimingChallenge` module，隱藏位置計算、回合與計分。外部 interface 為 `start(config, now)`、`step(now, input, output)`、`cancel()`；output 包含要顯示的有限視覺狀態及零或一個結算事件。時間與輸入由 controller 傳入，module 不自行讀 millis、SD、TFT 或 Pet Stats。

`MinigameController` 選擇遊戲、分派輸入與消費結果；顯示 adapter 把遊戲視覺狀態繪製成軌道、圖片與有限幾何圖形。以共用的效果提交 seam 套用結果，不能直接呼叫一個普通 User Action，否則會帶入動作動畫與其他動作語意。

### 狀態與判定

`Inactive → Prepare → AwaitRelease → Playing → Feedback → NextRound / Completed → Result → Inactive`。

- Prepare 先完成背景與第一幀，畫面就緒後才開始計時；進入遊戲的確定鍵不能成為第一發。
- AwaitRelease 要求三鍵全部放開，再接受新的單鍵按下事件。
- Playing 用整數三角波計算位置：先取經過時間對完整週期的餘數，再映射到 0..1000 往返。中間乘法使用足夠寬的整數，不用浮點或每 tick 加固定距離。
- 按下事件帶去抖後時間戳；依該時間的邏輯位置判定，不依最後一次 TFT 畫面位置。
- 命中區上下界都算命中；完美區先判定。按鍵時間恰好等於回合 deadline 算逾時，必須早於 deadline 才能作答。
- 一回合只接受第一個確定；左右單鍵無作答作用，同時多鍵不算射擊。按住不連發，放開後才可产生下一次操作。
- 結束標記只產生一次結果事件；Result 畫面重繪或再次 tick 不得重複加分。

邏輯更新不使用 delay。渲染可丟棄過期視覺幀，但不能把 missed tick 當成 missed shot；SD 長延遲讓題目無法正常呈現時，應中止本場並回報實際讀取錯誤。

## 5. 平台、結算與失敗處理

目前 `MinigameController` 受 ENABLE_GUESS_GAME 控制，`Game::handleCommandResult` 只有 startGuessItem 路徑；首版需要擴充為依遊戲索引啟動。既有 Guess Game 保持獨立，不改其既有獎勵。

目前 ButtonInput 一般操作在放開時發送且有 cooldown。建議增加小遊戲專用的去抖按下事件／時間戳，保留普通選單操作。遊玩期間停用作弊手勢，退出使用左右兩鍵持續 1 秒；組合鍵一經識別便消費其單鍵事件，要求再次全放開。這是新輸入政策提案，需要做既有按鍵回歸。

共用輸入 adapter 提議使用去抖之外的 30 ms 組合識別窗口；單鍵延後送出但保留原按下 timestamp。deadline 判定先等待窗口內候選事件識別完畢，再依原 timestamp 結算；不可因延後送出把原本有效的一發判成逾時。其他多鍵消費全部候選，不拆成多次單鍵操作。

建議遊戲期間暂停 PetClock，進入前先清空已到期的日數，返回時 resume，遊戲耗時不補算寵物日數。這會改變目前 minigame 仍 observe RTC 的行為，須在 Web 規格確認；不改全域兩秒 pet day，也不代替待辦 T05 的就寢模式。

活動遊戲阻止 STOP，保持可見亮度但仍服從低電壓限制；結果畫面最多停留 15 秒後返回。普通選單保留 30 秒調暗、120 秒 STOP。低電壓／RTC 故障／資源讀取失敗中止遊戲，經 controller 進入既有錯誤路徑。

整場完成才依結果表提交一批 Pet Stat 效果；效果原子性、夾限、保存 fingerprint 與播放失敗語意引用既有權威規格。中途退出、重新啟動或結算前故障不給獎懲；提交後視覺失敗不撤回。結果需有 session 結算旗標，保證同次運行不重複提交；不新增遊戲中存檔或跨重啟 exactly-once 保證。

建議結果提交後走現有保存流程並測試失敗通知；未成功寫入 SD 時不能宣稱結果已耐久保存。是否立即 saveNow 應在跨層契約定案，不另建一套保存機制。

## 6. 容量與 profile

提案只保留一個活動 session，使用固定大小狀態；沒有動態配置或腳本 VM。profile 只連結專案用到的模板，按已套用快照生成遊戲數、結果數、素材引用與效果容量。多模板共用一塊按最大活動狀態配置的儲存，不累加四份 session。

韌體只處理必要的有界讀取及 SD/TFT 執行失敗，不新增資料／圖片驗證。沒有任何 RAM/Flash 成本或 GD32 實機效能保證；需量測新增指標渲染、輸入與 controller 的連結差額、stack peak 及 SD 延遲。當前 platformio.ini 以 genericSTM32F103C8 建置，不能把它當成 GD32 板證明。

## 7. 實作順序與驗收

1. 確認按鍵、退出、時計政策與命中區语意；將正式資料契約寫到 Web。
2. 完成設定保存、素材指派、結果表與可操作預覽；正式匯出前驗證完整度。
3. 從同一編輯器快照匯出 fixture，建立純遊戲 module 與 controller／renderer 接入。
4. 完成 profile 裁切、結算、返回與平台故障處理；之後才逐步調整速度。

| 層級 | 必須驗證 |
| --- | --- |
| Web | 命中區／完美區邊界、缺圖可存不可匯出、結果表缺口／重疊、ID rename、入口可用性 |
| 跨層 | 匯出 fixture 的數值索引、素材、結果與 profile；host inspector 檢查完整契約 |
| 韌體 host | 邊界命中、deadline 同時按下、時間 rollover、卡頓後位置、按住不連發、一次結算、退出無效果 |
| 建置 | 未使用模板被裁切；單模板與全部模板 Flash/RAM 差額、配置不足的有界載入行為 |
| 實機 | 三鍵延遲、指標畫面與判定一致性、SD 延遲、TFT 殘影、低電壓與返回後 RTC／STOP |

預覽使用同一判定規則與可重現相位，仍不保證瀏覽器與實機輸入延遲相同。所有檢查均是未來驗收計畫，本次僅產生文件。
