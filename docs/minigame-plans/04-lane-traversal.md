# 路線選擇遊戲計畫書

日期：2026-10-11。狀態：設計提案，尚未實作、試玩或驗收。

把兵兵「匍匐閃地雷」抽象為離散路線與逐步結算模板，適用於過河、探索與障礙穿越。首版不是自動跑酷、物理碰撞或任意迷宮引擎。本文是使用流程與韌體計畫，新增正式匯出契約仍由 Web repository 管理。

## 1. 玩家會玩到什麼

玩家在二或三條路線間以左右鍵切換，按確定前進一步。每一列包含安全格與障礙格；依提示選路，每步立即回饋並結算對應 Pet Stat 效果，到最後一步完成。

與前三個模板不同，本模板首版採逐步提交。中途退出保留已完成步驟的獎懲，不額外發整場獎勵。這能保留兵兵每安全一步 +5、踩雷一次 −10 的語意，也避免退出取消已發生的踩雷懲罰。

## 2. 創作者如何設計

1. 新增「路線選擇」，命名並設定路線數、步數與每步時間上限。
2. 選擇地圖來源：「手動逐列配置」或「受限制隨機生成」。第一版只有安全／障礙兩種格子。
3. 手動模式用列×路線小表格指定障礙；隨機模式設定每列障礙數，系统保證至少一條安全路。
4. 選擇提示方式：「持續顯示本列」或「短暫預覽後隱藏」。預覽模式設定觀看時間，畫面明示現在是觀看或選擇階段。
5. 指派背景、玩家姿態、安全／障礙格、隱藏格、成功／受傷回饋及完成畫面；指定路線區域與角色原尺寸素材。
6. 配置「安全一步」與「障礙一步」效果。選項旁明示「每步立即生效；退出不撤回」。完成畫面首版只有視覺，不另外設定整場效果。
7. 預覽以固定地圖／seed 試走，查看每一步與夾限後數值，保存、套用并配置入口。

專用遊戲画布繪製当前列、玩家与步數，不承諾把所有遊戲變數接入現有 Screen Layout。圖片原尺寸使用；不符合尺寸契約時由 Backend 拒絕正式匯出，不由韌體縮圖或補邊。

### 建議設定與初始上限

| 設定 | 首版提案 | 說明 |
| --- | --- | --- |
| 路線數 | 2–3，預設 3 | 對應左右移動與確定前進 |
| 步數 | 1–32，預設 10 | 手動地圖最多 32 個列遮罩 |
| 每列障礙數 | 0..路線數−1 | 至少有一條安全路 |
| 提示方式 | 持續顯示／短暫顯示 | 首版沒有完全隱藏的運氣模式 |
| 短暫觀看時間 | 300–5000 ms | 就緒後開始計時 |
| 每步作答時限 | 1000–15000 ms | 超時中止整場，不自動踩格 |
| 回饋時間 | 100–1000 ms | 回饋期間不接受下一步 |
| 效果組 | 安全／障礙各一組 | 使用既有 Pet Stat 效果能力 |

上述容量為提案，尚未由 target build 接受。首版不提供 HP 歸零提前失敗、拾取物、分支地圖、任意格子效果或整場加權結果樹。

### 兵兵配置範例

三路、十步，安全一步體力 +5，踩雷一步體力 −10。兵兵原企劃未說明障礙提示可見時間、每列雷數與作答時限；不能把新設計的安全路保證與提示方式當成已證實的原版行為。

## 3. 匯出與驗證提案

Web 保存穩定遊戲／素材／Pet Stat ID；匯出投影成 runtime.bin 有界索引。設定包含路線／步數、地圖模式、提示方式、計時、素材角色，以及兩組逐步效果引用。

手動模式輸出每列一個障礙 bitmask；隨機模式只輸出路線數、步數與每列障礙數。首版隨機地圖每次進入生成一次，重繪／換道不得重抽；不保存地圖 seed 或局中進度。

Backend 驗證列數一致、遮罩有效、至少一條安全路、啟用模式設定與提示素材完整、位置／尺寸與效果引用、入口與 profile。互斥模式的殘留資料不輸出。是否能走到安全格不需路徑搜尋：每步可任意左右移動後確定，因此每列有安全格就可選安全路。

完整資料與資產驗證留在 Backend／host inspector。韌體只作必要有界讀取及實際 SD/TFT 故障處理，不驗證整張地圖、圖片尺寸或全檔 CRC；新增 section／版本正式定義在 Web。

## 4. 韌體如何設計

### 模組與 interface

新增 `LaneTraversal` module，提供 `start(config, now, randomSource)`、`step(now, input, output)`、`cancel()`。module 返回選中路線、當前列遮罩、提示／回饋狀態、`StepResolved(stepIndex, safe)` 或純完成事件。

controller 消費 StepResolved，通過既有效果提交 seam 原子套用兩組效果之一，再通知 module 接受下一步。提交事件使用 session ID 與 stepIndex 在本次運行去重；結果重繪不能重新消費。module 不直接操作 Pet Stats、保存或 TFT。

### 狀態與操作

`Inactive → PrepareRow → Preview / AwaitRelease → Choosing → ResolveStep → Feedback → NextRow / Completed → Result → Inactive`。

- 進入時起始路線為中間位置；二路時固定左路。之後沿用上一列選中路線，不每列自動回中。
- PrepareRow 決定本列障礙與顯示素材，畫面就緒後才開始觀看或作答時間。
- 短暫 Preview 階段不接受換道／前進；隐藏障礙畫面完成並全放開後才進 Choosing。持續顯示模式直接全放開後進 Choosing。
- 左／右在邊界夾住，不環繞；單次按下移一條路線，按住不連移。確定消費當前列一次。
- 判定只用列遮罩與選中路線，不依像素碰撞、圖片透明度或動畫位置。
- ResolveStep 產生一步事件後等待 controller 完成原子值提交。提交成功才增加步數、顯示回饋並进入下一列。
- 踩雷會消耗這一步並繼續；沒有原路重試、免費重新抽圖或退回上一列。
- 精確等於 deadline 的確定算逾時，中止且不消費本列。之前已提交的步驟保留。
- 左右組合為退出，消費其單鍵候選事件；其他多鍵不換道、不前進。回饋／下一列要求全放開，避免一按跨兩列。

隨機生成使用有界部分洗牌挑選不同障礙路線；路線最多三條，不能用無界重抽迴圈。生成整場遮罩至多 32 bytes，或保存固定乱數狀態逐列生成；首版建議整場生成以便測試與重繪一致。

## 5. 逐步結算與失敗語意

每步依安全／障礙結果提交一批 Pet Stat 效果，依權威規格夾限與原子更新。例如目前體力 95、上限 100，安全兩步 +5／+5 的實際值為 100／100；不能最後才把「安全數×5 −踩雷數×10」加一次，否則夾限順序會改變结果。

完成事件只有視覺，不再次加上累计效果。取消、timeout 或結算前讀圖失敗保留已完成步驟；當前未提交步驟沒有獎懲。提交後回饋圖失敗保留效果，依既有資源錯誤流程中止；不能為顯示故障重試該步。

結果效果不是普通 User Action，不帶入動作動畫或 Daily Change 暫停。controller 每步原子提交後更新既有衍生／解鎖狀態；若要延後 Evolution 至返回，必須在正式跨層契約確認，不能默默重排現有語意。

沿用既有保存流程，不新增局中存檔、地圖保存或持久 step 去重表。RAM 中已提交值會保留到退出；斷電是否保留最近一步由已成功的 SD 保存決定。若使用者要求每步斷電耐久，需要另外評估 saveNow、SD 寫入延遲與失敗處理，不能從本次計畫推導已獲授權的新持久化契約。

## 6. 輸入、時計與電源

目前 MinigameController 只有 Guess Game 路徑，新增遊戲目錄與模板路由；既有 Guess Game 保留。ButtonInput 目前放開才送一般 callback，建議提供去抖按下與時間戳給遊戲，保留選單輸入。活動期間停用作弊，左右兩鍵持續 1 秒返回；取消候選不產生單鍵事件，全放開後才恢復。

共用輸入 adapter 提議使用額外 30 ms 組合識別窗口；單鍵送出仍保留原按下 timestamp。deadline 先等待窗口內候選完成識別，不能把有效確定判成逾時；同時多鍵不得拆成先換道再前進。窗口增加的視覺反應延遲列入實機驗收。

建議進入前清空已到期的日數，遊戲期間 pause PetClock，返回 resume，不補算遊戲耗時。這會改變現有 minigame 時計，需使用者確認並記錄在 Web；不改普通兩秒 pet day 或待辦就寢模式。如此才能避免逐步效果與每日變更／Evolution 在同一步互相插入。

活動期間阻止 STOP並保持可見亮度，仍服從低電壓限制；沒有操作時每步時限保證有限等待。Result 最多 15 秒後返回；普通 30 秒調暗與120 秒 STOP 不變。RTC 故障、低電壓與資源讀取失敗中止，保留已提交值，不自動恢復半場。

## 7. 容量、實作順序與驗收

固定狀態為至多 32 個遮罩、路線／步索引、計時與上次提交步號。profile 只連結使用模板，按已套用快照生成設定／素材／效果容量；所有模板共用一個活動狀態區，不使用 heap、腳本或通用場景物件系統。

當前 PlatformIO genericSTM32F103C8 建置不代表 GD32 裝置可用。需要量測新增路線绘圖、按鍵、保存與 controller 的 Flash/RAM 差額、stack peak，以及 SD 同時讀圖與寫值的耗時。

實作次序：確認逐步結算與取消保留效果 → Web 正式契約与地圖編輯／預覽 → 真實快照匯出 fixture → 純 module → controller 效果／顯示／保存接入 → profile 與實機驗收。

| 層級 | 必須驗證 |
| --- | --- |
| Web | 手動列數、遮罩、每列安全路、模式切換、隐藏提示素材、逐步效果與 ID 引用 |
| 跨層 | 相同 fixture 的每列遮罩、兩組 effects、素材與 profile；host inspector 完整驗證 |
| host | 二／三路邊界、無環繞、每步一次、踩雷仍前進、deadline、預覽不能前進、rollover |
| 結算 | 每步 clamp 順序、同一步多 Stat 原子提交、取消保留已完成步、結果無重複獎勵、回饋失敗不撤回 |
| 回歸 | 效果後解鎖／Evolution 時機、保存失敗通知、輸入／作弊、時計 pause／resume |
| 建置／實機 | 模板裁切、RAM/Flash、SD 讀寫延遲、TFT 隱藏提示無殘影、低電壓与返回後 STOP |

Web seeded preview 不保證韌體乱數序列一致；跨層使用指定地圖 fixture。本次只有文件，未跑上述測試或裝置驗收。
