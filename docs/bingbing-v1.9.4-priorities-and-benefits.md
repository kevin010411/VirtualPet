# 兵兵功能優先順序與產品效益

日期：2026-10-10。根據使用者明確指定的順序記錄。這是產品方向與依賴分析，不是已實作功能、完成的跨層契約或實測結果。

最新範圍：使用者保留以下四項，新增睡覺觸發換日／數值結算與選單／子選單為必做；其他效益分析項目先暫緩。正式追蹤以 [功能開發待辦](bingbing-development-todo.md) 為準。

順序是使用者選擇的產品優先級。必要支援可作為該功能內的依賴交付，例如圖鑑的長期保存、小遊戲的進入／返回與結果結算；這不等於將完整子選單、所有存檔重構或原版十四天養成提前列為獨立優先功能。

## 50段顯示的覆蓋範圍

原始盤點是每積木32規則、全畫面64規則。此次同步修改前端、後端、匯出與韌體，實際profile容量隨已套用段數產生；同一project_29建置由400條規則改200條時，RAM由10,972降至8,572 bytes。

兵兵單項數值逐5顯示，含零值，所需不同值數量為：

| 數值範圍 | 不同值數量 |
| --- | --- |
| 0～300 | 61 |
| 0～400 | 81 |
| 0～500 | 101 |
| 0～600 | 121 |
| 總分0～1800 | 361 |

50段無法為上述任一範圍的每5分值都提供獨立圖片。可藉合併區間涵蓋全部有效數值，每段仍必須有圖片。精確數字或長條顯示是另一功能範圍；不自行提高指定上限，也不改來源圖片大小。

## 剩餘功能的編輯與遊玩效益

以下為產品分析與建議，不代表使用者已選定範圍或批准優先級。

| 功能方向 | 對創作者編輯的好處 | 對玩家的好處 | 建議與依賴 |
| --- | --- | --- | --- |
| 子選單與頁面導航（B01） | 把照顧、遊戲、收藏、設定分組；按鈕可連到頁面，主畫面不需放滿所有入口。 | 用三鍵仍能找到較多功能，返回路徑一致。 | 通用價值高；先為圖鑑／遊戲提供必要入口和返回，再討論完整多層導航。 |
| 動作條件、消耗與次數（B06、B05部分） | 能設定「能量足夠才能玩」「花一點體力換訓練」「每天最多幾次」；成功效果與消耗一起結算。 | 選擇有代價、養成有節奏，避免无限重複按同一動作刷值。 | 通用價值高；四款遊戲只需先有既定結果效果，通用消耗系統是另一範圍。条件動畫目前只改動畫，不會阻止效果。 |
| 派生數值（B05部分） | 總分由多數值計算，創作者不用在每個動作／事件手動維護另一個Stat。可重用於成長總分或進度。 | 長條、數字與實際結果一致，玩家能理解分數怎麼來。 | 通用價值高；先限定加總等必要運算，不直接引入任意公式語言。 |
| 條件效果與動態上限（B05、B09部分） | 按角色／階段改變獎勵與能力上限，可設計不同成長路線。 | 成長與解鎖有區別，換階段後還有追求目標。 | 有價值，但需獨立範圍；50段顯示本身不會提供這些規則。兵兵軍階只是其中一種設定。 |
| 回合／換日與定時事件（B07） | 可設計「按睡覺結束今天」或指定回合後進入下一階段，不只能依真實時間。 | 玩家控制步調，適合短局養成與任務，不必一直等待。 | 通用價值高；需與現有RTC日進度明确分工，避免兩種機制重複推進。完整14天排程不自動納入。 |
| 隨機事件（B08） | 編輯事件內容、權重、效果、訊息與外觀，能把現有角色素材變成日常故事。 | 每輪有變化，提高重玩動機；配合跑馬燈能清楚交代發生什麼。 | 通用價值高；適合在訊息能力之後評估。28條等機率是兵兵內容，不宜當通用系統固定規則。 |
| 分支成長、成就與結局（B09） | 依玩家累計行為配置路線與結局，可與圖鑑解鎖連結。 | 玩家選擇產生不同結果，收藏有獲得理由，完成一輪後仍想再玩。 | 通用價值高；沿用既有Evolution可用部分。軍階／軍種／體檢排程屬兵兵內容，不必先全部寫成平台專用功能。 |
| 情境按鍵與長按退出（B02） | 每款遊戲／頁面有一致操作規則，可區分選單鍵與遊戲動作。 | 小遊戲反應更直接，任何頁面都能清楚退出，減少誤觸。 | 四款遊戲的必要依賴；優先處理會影響判定的按下／放開時點及既有作弊手勢。 |
| 可操作教學／沙盒（B14） | 創作者能引導指定操作；試玩時不污染正式進度。 | 第一次知道按哪個鍵、如何得分；重看教學不會損失角色狀態。 | 有價值；先確認遊戲／導航模型再做，初期可用各遊戲簡短說明降低範圍。 |
| 長期收藏與本輪狀態分離（B17） | 分別設定重新開始要清除與保留的內容，便於成就、收藏與多輪遊戲。 | 重開遊戲仍保留已取得收藏與聲音設定，有持续累積感。 | 圖鑑的必要依賴；既有Pet save可沿用，但需確認新資料的版本與失配策略。 |
| 聲音設定、兵籍／資料頁（B16、B15部分） | 提供聲音開關與可選的詳細資料頁，讓主畫面保持簡潔。 | 可安靜遊玩，想看進度時能查詳細紀錄。 | 聲音開關是通用設定；詳細兵籍卡偏內容，可在計數／數值模型穩定後評估。 |
| 動畫與互動演出（B18） | 動作、訊息與外觀在一段流程內協調，能做開箱、抽籤、角色反應。 | 操作有回饋，解鎖與結局更有感。 | 遊戲所需舞台先隨遊戲處理。通用多物件／互動動畫是較大的功能，不能只靠增加動畫積木數量承諾完成；連續素材也需補齊。 |

## 不必現在變成平台新功能的部分

- 軍階名稱、軍種、15部隊、14天與體檢門檻、六結局文字、28事件內容：適合作為建立在通用能力上的兵兵專案設定；先不把每項兵兵規則都新增成固定System Command。
- 原版像素切點與任意重疊：只有要求原畫面位置完整還原時才有必要擴大版面能力；先保留素材原尺寸，依選定版面處理。
- 低電量、休眠、喚醒、基礎動畫與存檔：已有能力，工作在整合與驗收，無需當作全部重做的功能。
